# Agent 核心落地开发方案（方案 A）

## 目标

用户在计划页与 Agent 对话时，Agent 能主动判断需要哪些资料，自行读取当前计划、任务、报告、长期档案和计划来历，再给出有依据的回答；需要修改计划时生成待确认建议，需要更新长期档案时生成带来源的新增或取代提案。Agent 永远不能绕过用户直接写入业务数据。

## 范围

要做：
- 把现有计划对话升级成带上限的工具循环。
- 增加四个只读工具：读取当前计划、最近报告、长期档案、计划来历。
- 复用现有 `plan_change` 提案完成计划修改。
- 补齐档案“新增 / 取代”两种动作及来源、置信度、事实时间。
- 保存每轮 Agent 的运行结果和工具使用摘要，便于排错。
- 在现有计划页展示本轮读取依据、停止原因和确认条。

不做：
- 不读取本地知识库、任意文件或网络。
- 不做向量数据库、Embedding、LangGraph、多 Agent、后台自主运行。
- 不建通用聊天首页。
- 不允许 Agent 直接打勾、跳过、交付、作废或删除。
- 不改变四问判断链路。
- 不引入新的第三方 Agent 框架。

## 核心设计

### 1. 工具循环

新增 `backend/app/agent_runtime.py`，负责统一循环：

1. 接收当前计划、用户消息、最近对话和工具清单。
2. 模型返回两种结果之一：
   - `tool_calls`：请求一个或多个只读工具。
   - `final`：最终回复，可附现有 `plan_change` 建议。
3. 系统校验工具名称与参数，执行后把结果送回模型。
4. 最多 3 次模型调用、最多 6 次只读工具调用；结构错误重试也计入上限。
5. 到达上限仍无法回答时，明确返回“读取了什么、还缺什么”，不生成猜测或提案。

一次模型调用允许批量请求多个工具，避免恢复“五圈循环”后与现有三次调用纪律冲突。

### 2. 工具边界

新增 `backend/app/agent_tools.py`，只注册以下工具：

- `read_current_plan`：目标、计划状态、阶段、任务、截止日、落后情况。
- `read_recent_reports`：当前计划最近 5 份报告。
- `read_profile`：当前有效档案，可按类别读取。
- `read_plan_origin`：候选来源、规划对话、已采纳蓝图。

当前计划编号由系统注入，不交给模型选择，防止读取其他计划。工具只返回结构化结果，不接受 SQL、路径或任意接口地址。计划修改继续使用现有 `plan_change` 校验与裁定链路，不另造写入口。

### 3. 上下文管理

每轮上下文固定分为：
- 系统规则和安全边界。
- 当前用户消息与必要的最近对话。
- 工具目录，不预先塞入全部业务数据。
- 本轮工具返回结果。
- 剩余模型调用次数和工具次数。

工具结果中的用户文字只作为“事实材料”，不得覆盖系统规则。各工具保留独立字符上限，总上下文超限时优先保留当前问题、最新事实和被引用的依据，删除更早的对话。

### 4. 运行记录

新增 `agent_run` 表，每条用户消息对应一次运行，只保存：
- 所属计划与对话消息。
- 完成、失败、达到上限三种结果。
- 模型调用次数、工具调用次数、停止原因。
- 工具名称、参数摘要、成功与否、耗时。

不重复保存完整计划和档案正文。现有 `llm_call` 继续负责模型成本记录，`agent_run` 只负责解释这一轮 Agent 做了什么。

### 5. 长期记忆

扩展 `profile_change` 提案为明确的两种动作：
- `add`：新增档案。
- `supersede`：取代一条当前有效档案，必须带旧档案编号。

新增 `profile_evidence` 表，把批准后的档案与证据关联起来，至少记录：
- 来源类型，本阶段只支持计划对话。
- 来源消息编号和一句原文。
- 置信度：确定 / 存疑。
- 事实发生或被确认的时间。
- 提炼时间。

“存疑”不直接产生可批准的写入提案，只返回待核对提示。批准取代时复用现有 `profile.supersede_item`；旧值留痕但不宣称已经支持一键回退。

## 顺序任务

### 阶段一：Agent 会主动读取

- 先把上述输出契约、工具清单和限制写入 `docs/SPEC.md` 与 `tasks/todo.md`。
- 实现 `agent_runtime.py`、`agent_tools.py`。
- 改造 `dialogue.say`：从一次性拼完整上下文，改为工具循环。
- 保留现有最终回复和 `plan_change` 建议形状。
- `POST /api/plan-dialogue` 只新增可选的 `run`、`tools_used`、`stop_reason` 字段，不删除或改名现有字段。
- 计划页在助手消息下提供折叠的“本轮依据”，只显示工具名称和结果摘要。

可观察结果：询问“我现在先做什么”时，Agent 自己读取计划；追问“结合我最近状态判断”时，才继续读取报告或档案。

### 阶段二：档案成为可信长期记忆

- 增加 `profile_evidence` 表与初始化迁移。
- 扩展档案提炼输出和 `profile_change` 提案契约。
- 批准新增时写档案与证据；批准取代时旧档案进入被取代状态，新档案成为当前值。
- 批准前重新检查目标档案仍然有效，避免旧提案覆盖后来修改。
- 档案页显示“依据、置信度、事实时间”，没有证据的历史档案标为“手工录入”。

可观察结果：用户说“以后每周只能投入两小时”，点击现有档案提炼入口后，可以看到它准备新增还是取代哪条档案，以及依据的是哪句话。

### 阶段三：失败收口与界面完成

- 工具不存在、参数非法、模型结构错误、达到调用上限时返回统一中文错误。
- 失败运行不落计划提案、不改档案。
- 确认计划建议后沿用现有台账；忽略仍记录“聊天里先不动”。
- 完成前统一更新 SPEC、任务状态与 HANDOFF，删除被新运行时取代的旧上下文拼接代码，不保留两套执行路径。

## 验证策略

后端焦点用例：
- 模型先请求计划，再正常回答。
- 一轮批量读取计划与报告。
- 非法工具、跨计划参数、超过调用上限被拒。
- 失败时不产生任何提案或业务写入。
- `plan_change` 确认前不改数据，确认后走原有台账。
- 档案新增、取代、目标已失效、证据持久化四条路径。

最终验证：
- `pytest -q`
- `python tools\smoke_p1.py`
- 前端执行 `npm run lint`
- 前端执行 `npx tsc --noEmit`
- 前端真实交互由用户手工走查，不增加自动化浏览器测试。

## 用户手工走查

1. 在计划页问“根据目前进度，我下一步先做什么”，确认能看到本轮读取了计划。
2. 再问“结合最近执行情况判断”，确认它按需读取报告，而不是每轮加载全部资料。
3. 要求调整截止日，确认未点按钮前计划不变，点“确认”后才修改并留下台账。
4. 告知一条长期状态变化，执行档案提炼，确认能看到新增或取代、依据原话、置信度和时间。
5. 用测试桩触发调用上限，确认页面说明缺口且没有产生提案。

## 授权与边界

实施前一次性确认两项数据库增量：
- 新增 `agent_run`。
- 新增 `profile_evidence`。

这两项只增表，不清库、不删除或批量改写现有真实数据。不得修改本地知识库、增加外部依赖、引入联网读取或扩大为通用助手；任何范围扩张重新请示。

## 完成标准

- Agent 能在计划对话中自主选择并调用只读工具。
- 三次模型调用上限真实生效，所有停止都有明确原因。
- 所有计划与档案写入仍需用户确认。
- 档案支持新增和取代，并能追溯到对话原话。
- 现有计划对话、计划建议、提案裁定和四问链路没有回归。
- 最终四条验证命令通过，用户可按五步走查完整体验。


# 执行策略修订：本阶段剥离记忆系统

本补充覆盖《Agent 核心落地开发方案（方案 A）》中与记忆开发冲突的范围；Agent 的安全边界不变。

## 本阶段定位

本阶段只落地 Agent 核心的三个板块：

1. 循环：受控工具循环、调用上限、停止与失败收口。
2. 工具：按需读取当前计划、报告、现有档案和计划来历；计划修改继续走提案确认。
3. 上下文管理：按需取材、分区限长、工具结果回填和上下文裁剪。

现有长期档案只作为 Agent 的一个只读信息来源。本阶段不改造记忆系统。

## 从原方案删除

- 删除“长期记忆”章节中的全部开发要求。
- 删除“阶段二：档案成为可信长期记忆”。
- 不新增 `profile_evidence` 表。
- 不扩展 `profile_change` 为新增 / 取代联合协议。
- 不开发来源、置信度、事实时间和存疑项。
- 不修改档案页及现有档案提炼流程。
- 删除对应的档案新增、取代、证据持久化测试和手工走查。
- 原授权清单只保留 `agent_run`；不再包含 `profile_evidence`。

## 保留边界

- 保留 `read_profile` 只读工具，读取现有有效档案。
- Agent 当前循环所需的目标、工具结果和剩余额度，只作为临时运行状态，运行结束即清空；这不代表记忆模块已经落地。
- `agent_run` 只用于排错和解释本轮调用过程，属于运行审计，不属于 Agent 记忆。
- 工具注册方式应允许未来增加“检索经历记忆”等工具，但本阶段不得提前实现。

## 本阶段完成标准

- Agent 能自主选择并调用四个只读工具。
- Agent 能在最多 3 次模型调用内完成回答或如实说明缺口。
- 计划修改仍需用户确认，失败时不产生提案或业务写入。
- 上下文不再每轮预装全部业务资料。
- 现有档案、档案提炼和四问链路保持原状。
