# 记忆走查整改开发方案（2026-09-21）

> **状态：2026-09-21 两批全部实现**（规格落 SPEC 决策 43，逐条验收与实施记录见 `tasks/todo.md` 的 P3.10：T42 复核日期 · T43 散文兜底与提示词拆层 · T44 报错人话与中文别名 · T45 记忆变化感知）。本文件是当时的设计记录，实现与原方案一致；两处实现细节按本文件「风险与回退」的判断落：墓碑表加列走 `db.init` 加列迁移，散文兜底只在重试之后生效。

来源：用户真机走查 `/memory` 与计划对话后提出的四条（记录在 `docs/记忆系统.md` 的「走查反馈」一节）。四条口径已全部定稿：第 1、2 条由用户当场同意，第 3、4 条按本方案作者（Agent）的推荐定稿。**本文只写怎么改，不改代码。**

总原则一句话：**要系统动手的必须严格，只给用户看的可以宽松；感知靠摘要，依据靠整份重读。**

## 分批

- **第一批（小改动，不碰模型行为主体）**：第 1 条日期选择、第 2 条散文兜底与提示词拆层、第 4 条工具报错人话。
- **第二批（动提示词与运行账的读法）**：第 3 条记忆变化感知。
- 分批的理由：第一批全是「界面 + 验收分支 + 报错文案」，第二批会改变模型每轮读不读记忆的行为；两批一起上，走查时分不清「它这次读没读」是哪个改动的效果。

## 第一批

### 第 1 条：「还作数」带日期选择

- **前端**（`frontend/app/memory/page.tsx`）：待复核那一行的「还作数」从一键改成「点开出现日期输入框 + 确认」，输入框**预填今天 + 90 天**（沿用后端现有默认，不改后端）；确认后调既有的复核接口并带上所选日期。
- **显眼化**：凡带复核时间的记忆（当前记忆与待复核两栏都算），在条目上常驻一行「下次复核：YYYY-MM-DD」；到期时那行变成「已到复核时间 · 不再当依据」。现在这个日期只出现在操作回执的一句话里，用户走查时误读成「永久生效」。
- **后端**：不改（复核接口已接受显式日期）。
- **测试**：后端补一条「显式日期优先于默认 90 天」；前端 lint / tsc。

### 第 2 条：回话散文兜底 + 提示词拆两层

- **验收分支**（`backend/app/agent_runtime.py`）：最终回话的验收改为三段式——① 输出是合法信封，照旧；② 不是 JSON，**带原因重试一次**（保留，这是在教模型套壳）；③ 重试后**仍然**不是 JSON 但有一段非空散文 → 把这段散文当回话收下、建议记为空、运行账的停止原因写明「用了散文兜底」。**「要读资料」与「建议」两条路一行不动**：没有 `tool_calls` 数组就不算读资料，散文里永远解析不出建议（所以不会落任何提案）。
- **兜底落在代码里、不落在提示词里**：提示词仍要求套壳，模型 slips 时才由代码接住。实现上给循环加一个「散文验收器」回调（由 `dialogue.py` 提供：`extract_json` 取不到对象且去空白后非空 → 返回那段文字，否则返回空），循环只在**已经重试过一次之后**才问它。
- **提示词拆两层**（`backend/app/dialogue.py`）：把现在混在一起的 `SYSTEM_PROMPT` 拆成 `CONTRACT_PROMPT`（两种输出形状、校验口径、不许 Markdown 代码块这类**契约**）与 `STYLE_PROMPT`（说人话、别客套、默认两百字以内这类**风格**），调用时拼成契约 + 风格。**契约段视为代码的一部分**（改它等于改接口），风格段是以后调语气、甚至做设置项的唯一入口。工具目录本就由注册表自动生成，保持独立。
- **测试**：① 散文 → 重试 → 仍散文 → 收下为回话、建议为空、运行账 ok 且带兜底说明；② 散文 → 重试 → 合格信封 → 走正常路；③ 散文里写着「我想先读计划」但没有 JSON → **不**被当成读资料；④ 散文兜底永不落提案；⑤ 契约段与风格段拆开后再拼起来，目录与校验行为不变。

### 第 4 条：工具报错人话 + 中文别名

- **别名**（`backend/app/agent_tools.py` 的读档案工具）：类别参数同时接受五个约定令牌**和它们的中文名**（「当前状态」→ `current_state`），模型写中文不再被判错。
- **报错人话**：类别仍不认时，报错改成「类别只能是 生活习惯 / 生活记录 / 当前状态 / 短期目标+痛点 / 长期主线 之一（你写的是「…」）」——**不再把五个英文令牌甩进「本轮依据」**。其余工具的报错本来就是中文人话，只统一检查一遍措辞。
- **测试**：中文别名读到的是同一批档案；非法类别的报错文本含中文名、不含令牌列表；运行账里的摘要读得懂。

## 第二批：第 3 条 记忆变化感知（摘要 + 整份重读）

**要解决的问题**：模型每轮从零决定读什么，没有任何东西告诉它「记忆库自你上次读之后变过」，而对话历史里还留着它早先（记忆变化之前）的判断，于是它沿用旧认知不重读（走查截图 2）。

**方案**：增量只用来生成一句提醒，依据仍靠整份重读。

1. **水印（不加列）**：这段对话上次读记忆的时间 = 该计划的运行账里、最近一条「读成了 `read_memories`」的运行记录的时间。运行账本来就记着每轮读了什么、何时读，直接查，不给对话表加状态列（对话表是追加式日志，这个项目的老规矩）。
2. **变化清单**：水印之后的记忆变化，从台账流水取（新增 / 取代 / 作废都带时间戳），**彻底删除并上墓碑表**（删除后记忆行没了，只有墓碑知道）；为此给墓碑表补一列可空的计划编号（加列迁移，老行不受影响），否则计划内记忆被删后算不出「是哪个计划的事」。范围按作用域切：全局记忆的变化对所有对话都算，计划内记忆的变化只算它那一个计划。
3. **摘要行**：有变化时，在每轮开头（工具目录与额度那一段之后）多一行——「记忆库自你上次读（时间）之后变过 N 条：#15 被取代、#33 作废、#7 被彻底删除。涉及它们就先读一次记忆。」没有变化、或这段对话从没读过记忆时，**不出现这一行**（从没读过的对话历史里没有基于记忆的结论，风险小，不硬塞噪音）。
4. **硬规则进契约段**：「出现上面那行时，本轮必须先调用读记忆一次再回答。」读的是整份当前值（既有工具，两千字封顶），不是增量——只给增量时旧文本还躺在历史里，压不住旧认知。
5. **代价（明写）**：摘要行每轮多几十字；硬规则会占掉一轮六次读资料额度里的一次，在它还要读计划与报告的那一轮里挤一点位置。可接受。

**测试**：① 记忆在水印之后变过 → 摘要行出现且列对动作；② 没变 → 不出现；③ 从没读过记忆的对话 → 不出现；④ 另一个计划的计划内记忆变化 → 本计划对话看不到；⑤ 彻底删除进摘要（走墓碑）；⑥ 契约段含硬规则；⑦ 摘要出现的那一轮，运行账里能看到它真读了记忆（这条留给用户真机走查确认）。

## 验证与走查

- 每批结束：`pytest -q`、`tools\smoke_p1.py`、前端 `npm run lint` 与 `npx tsc --noEmit`。
- 第一批走查（用户）：待复核点「还作数」能选日期、新日期常驻可见；在计划对话里故意让它 slips 一次（比如问一句不需要资料的闲话）看是否还有红条；「本轮依据」里不再出现英文令牌串。
- 第二批走查（用户，**要接真模型**）：先聊一轮 → 去记忆页改一条记忆 → 回对话问相关的话，看它这一轮是否主动重读记忆、「本轮依据」里有没有读记忆。

## 风险与回退

- 第 2 条的兜底只在「重试一次之后」生效，最坏情况等于今天的行为减去一次失败，回退就是删掉那个回调。
- 第 3 条的摘要与硬规则都在提示词里，回退 = 删那两行，不动任何表与接口。
- 唯一动表结构的是墓碑表加一列计划编号（可空、加列迁移），与本项目历次加列同一套路。

## 不做的事

- 不做「只读增量当依据」（压不住历史里的旧文本，且要并三处来源，漏一种就是暗坑）。
- 不做「一变就无条件全量重读」（没有摘要它连理由都没有，等于没感知）。
- 不把风格段做成设置项（先拆出来，设置项等真有人要调再说）。
- 不动四问、候选、蓝图那几条链路的输出契约（它们各有各的验收，本次只碰计划对话这一条）。
