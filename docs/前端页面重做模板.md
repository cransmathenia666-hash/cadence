# 前端页面重做工作约定（PC 优先）

> 现行视觉方向见 `docs/前端设计方向.md`；产品行为见 `docs/SPEC.md`。本文取代旧版“七步复刻模板”的通用地位。此前 `design-samples/real-round*/brief.md` 与三页分阶段方案只记录当轮决定，不作为新页面的硬性风格要求。

## 开工前

读当前页面及相关组件，列清主任务、信息优先级、真实动作、等待/错误/空态和不能改变的业务后果。先画出 PC 首屏与点击后的阅读关系：哪些始终可见，哪些进入相邻区、主视图或临时层；确定页面独有的构图和一个有理由的视觉重点。新方案可以推翻旧页面的视觉外形，但不得编造数据、无故删去可追溯依据、做出没有真实动作的按钮，或自行改写后端裁定规则。

## 设计与实现判断

- 组件跟随内容，不按“对话页双栏、列表页胶囊行、表单页居中大卡”套模。目录、轨迹、章节、对话、差异对照、台账各用最能解释关系的形态；相邻区域的大小、密度与留白可以不对称。
- 页面不能成为满屏同型卡片或卡套卡。用文字尺度、轴线、细分隔、留白、局部表面组织层级；独立容器用于确实要圈定的输入、裁定或浮层。圆角使用主题令牌按语义分级，不把胶囊和大圆角当全局风格。
- 点击必须有明确的信息去向和返回路径。详情可切换主阅读区、在并列评审席显示、进入抽屉或局部展开；就地展开只适合简短补充，不机械地在下面追加一个框。选择态、关键后果、不可用原因要看得见。
- 保留现有颜色与动效令牌作为实现基础，必要时在明确的视觉决策下调整；参考站与 `ui-foundry` 是可选零件，不承担验收标准。交互要有真实反馈、键盘焦点和可理解的空/错/等待态，不靠统一 hover 缩放或连续入场动效制造“精致”。
- PC 是本轮审美评审对象；移动端暂不优化，但已有功能不得被改到无法使用。浏览器里的真实视觉与操作感由用户手工走查，不用截图像素或 DOM 数值代替审美判断。

## 交付检查

前端代码发生变动时，在 `frontend` 运行 `npm run lint` 和 `npx tsc --noEmit`；接口或后端写入语义变动按项目 `AGENTS.md` 另行验证。静态检查只证明代码层面未报错，不等于页面好看或操作顺手。交付时说明改了什么构图、点击后内容怎样出现、哪些真实操作仍待用户走查；用户在 PC 端检查主次、容器与圆角密度、长内容阅读、关键动作和异常状态。本轮若仅修改设计文档，不机械运行前端检查。

## 仍值得注意的实现事实

- `frontend/app/cadence-theme.css` 负责主题基础；页面进现有壳时核对 `dark` 作用域、滚动区域与根容器，不照搬旧页的全屏高度。
- `HoverSelect`、按钮反馈和其他现成组件按当前任务选用，不预设所有选择器都必须悬停打开。新交互必须兼顾键盘与明确的打开方式。
- 异步切换计划或候选时防止旧请求覆盖新视图；失败要保留用户输入与已有内容。具体行为以相关页面和接口现状为准，不把旧任务书中的实施细节当成永远有效的约定。
