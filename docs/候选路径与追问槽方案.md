> **状态：方案已定、待排期开工。** 2026-09-20 用户点头授权下文那一项加列，但明确本轮只写方案、不写代码。
>
> 2026-09-20 由用户走查触发：他输入了一个明确方向（「学 agent 开发怎么学」），「找」回了他**一条路上的五个先后步骤**，
> 却按五个互相竞争的方向摆出来——每条独立采纳/否决，而否决＝永久拉黑。他的原话：「五个连续性的方案，不应该独立」
> 「是否确定否决可以在后续的讨论中进行」。同日他还指出追问槽「有追问、没有输入框」。
> 本方案把这三件事一次收口：**候选层只裁定方向，步骤的去留往后放；阶段补一个「不要」的出口；追问槽保留但改契约、补入口。**

## 目标

用户说清一个方向时，「找」给的应该是一条路（一个方向 + 它的几个先后步骤），而不是五个方向。
这条路在清单上只裁定一次（走 / 不走）；步骤建不建，在蓝图勾选时定；建出来之后不要哪一步，在计划页跳过。
「不要」这件事在三层各有一个语义正确的出口，互不串味，也**不再有任何一步会被误拉进永久禁区**。

## 范围

要做：

- 「找」的输出多一个**形状**：`path`（一条路）或 `directions`（几个方向，现状）。
- `path` 时清单只落**一条伞候选**，步骤作为草案存在它的 payload 里；清单页渲染成一张卡。
- 采纳伞候选＝建伞阶段 + 把步骤草案带进规划对话，作为出蓝图的底稿。
- 新增**阶段跳过**（理由必填、台账留痕），补上「建出来之后不要某一步」的出口。
- 追问槽补真输入框，回答自动并入下一轮输入；已答过的追问进反馈流水，不再重复问。

不做：

- 不做节点真删除（理由不变：报告与交付物指着节点编号，删了引用全断；「不算数」由跳过表达）。
- 不让 Agent 提「跳过」建议——跳过仍是人自己点的执行动作（与打勾/交交付物同纪律）。
- 不跳过规划对话：采纳后仍先聊再出树（决策 36 不动），草案只是底稿不是成品。
- 不动四问判断链路、不动禁区机制本身（它继续服务于**方向级**否决）。
- 不新增表；只给 `candidate` 加一列（见「授权与边界」）。

## 核心设计

### 1. 两种形状，两种裁定语义

模型这一轮先自报形状：

- `directions`（现状）：3–5 条互相竞争的方向，逐条采纳/否决。否决＝永久禁区，语义是「这条路我不走」。
- `path`：**一条伞候选**（标题是这条路本身，如「从零到部署学通 agent 开发」）+ `steps`：2–8 个先后步骤，
  每步 `{title, deliverable, why}`（形状取蓝图 stage 的子集）。清单页是一张卡：伞标题 + 步骤列表（只读）+
  「采纳整条 / 否决整条」两个按钮 + 一个形状标签（「这一轮它给的是一条路」），它选错形状你一眼能看见。

`path` 时**步骤不单独否决、不进禁区**——「这步暂时不用」不是「这步永远别给我」，前者有后面的出口，后者没有。
伞候选的否决仍是永久禁区，因为它否决的是方向，语义正确。

校验沿用老规矩：形状字段缺失/取值不对、`path` 的步骤少于 2 或多于 8、步骤缺 title 或 why，一律判不合格带原因重试一次，
两次仍不合格如实报错、一条都不落。

### 2. 采纳一条路：建伞阶段 + 草案进对话

采纳伞候选沿用决策 27：建一个同名伞阶段（过同一道防重名闸）。同时把 `steps` 写进两处以供后续使用：

- **规划对话的上下文**多一段「步骤草案」：模型被要求以草案为底稿增减（可以合并两步、可以补一步、可以删一步），
  而不是从零再问六轮；对话区顶部也把草案列出来给你看。
- 出蓝图时步骤自然成为蓝图的阶段，**勾选**决定建哪几步——不勾＝本版不建，不进任何黑名单，想要再出一版还能捡回来。

这一步不新增容器：草案住在 `candidate.payload`，对话与蓝图都是现成的。
想只取其中几步也有两条现成的路：在规划对话里直接说（模型按你说的增减草案），或出蓝图时不勾——
两条都不进禁区，下一版还能捡回来。

### 3. 「不要」的三层出口（语义表）

| 层 | 动作 | 语义 | 后果 |
| --- | --- | --- | --- |
| 方向（清单） | 否决伞候选 / 否决某条方向 | 这条路我不走 | 永久禁区（现状不变） |
| 蓝图（勾选） | 不勾某一步 | 这一步本版不建 | 什么都不留，下版可捡回 |
| 计划（已建） | **跳过阶段**（新）/ 跳过任务（现状） | 这一步不做了 | 台账一句理由，回答「当时为什么没做」 |

**阶段跳过**的规则照抄任务跳过：理由必填、走台账 `set_status(skipped)`、跳过视同完成（阶段完成判定直接满足，
同「没有任务的阶段」那条逻辑）；其下任务**原样留着**（它们是痕迹，不是待办）；落后量不再算它（与任务跳过同口径）。
界面在阶段行给一个「跳过」入口（与任务的并排），计划页的完成度文案把「跳过」算进去（现状已如此）。

### 4. 追问槽：保留，改契约，补入口

**保留的理由**：追问发生在**采纳之前**——那时还没有规划对话，而模型缺的往往是一句关于你的事实
（「是为了求职还是做内容」这类），缺了它排序就是猜。砍掉它等于让「找」在信息不足时只能硬排五条再标一句依据不足。

**但它与规划对话必须各管一段，区分写进规格**：

| | 追问槽 | 规划对话 |
| --- | --- | --- |
| 时机 | 采纳**之前**（清单页上方） | 采纳**之后**（清单页下方展开） |
| 问的对象 | **关于你的事实**（档案缺的那一类） | **关于这条路怎么走**（意向、节奏、取舍） |
| 形状 | 一个问题、一个输入框、一次提交 | 多轮对话线程，终点是蓝图 |
| 记忆 | 回答并入下一轮输入 + 进反馈流水 | 自己的历史（6 轮上限） |

配套改动三条：

1. **补真入口**：黄色追问条下面放一个输入框 + 「带着这个回答再问一轮」。提交时把**原问题 + 你的回答**拼成下一轮输入
   （追问本身不落库，不拼上原问题，下一轮模型就丢了前提）。
2. **收紧问的范围**：提示词与校验都钉死——追问只能问档案里缺的那一类事实、一句话能答；问「这条路怎么走」判不合格
   （那是规划对话的活）。
3. **问过的不再问**：已答的追问（问题 + 回答一句）进该轮的反馈流水行，后续轮次的 prompt 看得到，模型不得重复问同一事实。

## 用户手工走查

1. 输入一个明确方向（如「学 agent 开发怎么学」），确认清单是**一张卡**（一条路 + 步骤列表），不是五条独立候选。
2. 采纳它，确认计划里多一个伞阶段，且规划对话里能看到步骤草案、模型以它为底稿聊。
3. 出蓝图时不勾其中一步，确认它没被建、也没进禁区（下一版蓝图里它还在）。
4. 在计划页跳过那个伞阶段（填理由），确认阶段完成度满足、落后量不再算它、台账有那句理由。
5. 触发一次追问，确认追问条下有输入框；回答后再问一轮，确认模型不再重复问同一件事。
