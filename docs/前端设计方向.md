# Cadence 前端设计方向（PC 优先，2026-09-29）

> 这是新页面与重做页面的现行视觉判断依据，不是旧样张的复刻说明。业务事实与交互契约以 `docs/SPEC.md` 和当前实现为准；本文件管构图、信息呈现与审美取舍。`design-samples/real-round*/brief.md` 是各轮历史任务记录，里面的“硬标准”和源站对照不再凌驾于本文件。移动端暂不做审美优化，不能因此破坏已有基本可用性。

## 想要的气质

深色、安静、有编辑意识的决策工具：让用户一眼看见此刻要判断什么、材料之间是什么关系、动作会改变什么。可以有强烈的不对称、尺度反差、密度变化和少量独特细节；不追求每块都安全、均匀、圆润。允许某处构图有性格甚至争议，但不能用创意掩盖事实、裁定条件或关键操作。

## 每页先定构图，再选组件

1. 先写下这一页的主动作、主阅读对象、辅助证据和可暂时隐藏的信息。首屏要有明确主角，不能把每种内容做成同尺寸、同明度、同边框的卡片。标题、宽度、留白、对齐轴、密度和位置都能建立层级；“加一层框”是最后的选择。
2. 根据内容关系决定形态，而非根据组件库决定形态：连续对话是流，多个方向是目录与评审关系，单条完整路径是有先后与分支的轨迹，任务是章节/台账，裁定是待办与证据的对照。它们不必共享一种列表或折叠卡外观。同页也要有主从与疏密，不做平均分栏。
3. 表面只用于真正需要独立边界的东西（输入、裁定、悬浮上下文、可移动/可选择对象）。长段文字、依据、时间、状态和列表可直接落在页面底色上，用排版、距离或必要的细线组织。禁止卡套卡和整页等宽卡片墙；不是禁止一切卡片。
4. 点击应改变用户阅读信息的方式：可以切换主视图、让相邻阅读区承接详情、进入专注态或覆盖式抽屉，并保留清楚的返回与当前选中线索。只有短小、低频的补充材料才适合就地展开；不把“下面多一个同型内容框”当作默认交互。关键裁定后果与当前状态不能藏到点击后。
5. 一个页面可有一个鲜明的视觉动作（尺度突变、跨栏标题、纵向索引、时间轨迹、局部亮面等），但它必须帮助理解内容或操作，不把每一块都做成焦点。不同页面不强求重复相同的大胆动作。

## 令牌与细节的使用边界

- `frontend/app/cadence-theme.css` 是当前实现的颜色与半径令牌来源。保留近黑表面、节制的亮色文字和语义色；不再规定“纯白只能给用户消息”“蓝色必须是主行动”这类僵硬映射。状态不能只靠颜色表达，正文与操作不能为了氛围暗到难读。
- 圆角按对象而定：小控件、浮层、独立表面可以使用现有分级令牌；章节、台账、分隔、阅读区域可以平直。胶囊只在标签或确实需要柔软触感的小物件上使用，绝不一律 `rounded-full`。直角不是缺陷，圆角也不是品质保证。
- 阴影、描边、底色变化都只是分层手段。内容之间可以用空白、细线、编号、左侧索引或排版轴线；不规定“只能浮起，不能分隔”。间距和文字大小由阅读距离、信息密度与层级决定，不套用全站 40px 区块距或 11px 元数据。
- 动效只解释状态转换、选择与反馈；按钮不必统一弹簧缩放，回复不假装实时逐字流出。键盘焦点、错误、等待、空态与减少动态效果的偏好必须可辨，装饰性运动不能抢阅读节奏。
- beui.dev、beautifului.dev 和现有组件库仅是手法与实现参考，不是品牌标准或像素验收对象。借一个恰当的交互可以，不能把它们的组件陈列方式搬成 Cadence 的信息架构。

## 评审一页时问什么

闭眼回想首屏：能否说出主角与下一步？把边框去掉后，层级是否仍成立？备选方向与完整路径是否一眼属于不同的信息形态？点击之后，信息是否去到了更适合阅读的位置，而不是单纯向下添框？每一个独立容器、圆角和动效是否有语义理由？最后核实实际业务动作、可追溯依据、键盘操作及异常状态；视觉判断由用户在 PC 端手工走查，不把静态检查或源站截图当作审美验收。
