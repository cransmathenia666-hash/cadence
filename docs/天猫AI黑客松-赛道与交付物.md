## 开发层关注点

### 必须先看的三个数字

1. **AI 应用能力 = 25%**，单项权重最高。评的是「AI 是否**深度参与作品核心功能或创作过程**」——套一个 API 做聊天框会被扣分，AI 必须是作品主干。
2. **初赛 = 专业评审 80% + 网络投票 20%**。人气不是重点，别在拉票上花力气。
3. **TOP24 晋级**。名额极少，作品完成度必须扎实；但初赛**不要求完整成品**，要的是「能完整呈现核心功能与体验」的 Demo。

### 两个硬性缺项（不满足直接不合规）

- 作品包必须有 **≥1 项 AI 实践佐证**（模型调用截图 / 关键代码 / Prompt / 运行页面 / API 记录 / 日志）。
- 作品封面必须 **1920×1080 的 16:9 横版**，≤10MB。

### 加分项设计空间

- **端云协同**：结合本地 AI PC 算力 + 云端模型 / 服务完成核心功能，需在「AI 技术实践说明」写明本地端与云端各自承担的能力及协同方式。这是规则里唯一明写的技术加分。
- **软硬件协同**：软硬协同方案亦可加分【官方·页面】。

### 交付形态约束

- 作品形态不限：Agent、软件 / 应用、内容工具、互动体验、AI + 智能设备等均可。
- 但**必须提交作品包（zip）**且包含可验证材料，不能只交文案或方案。
- 「作品介绍」与「AI 技术实践说明」各自**上限 300 字**，须精炼；作品名称上限 **30 字**。
- 交稿窗口可反复更新，**以 2026-10-07 截止前最后一版为准**——可先交一版占位再迭代，但勿在临近截止时覆盖稳定版。

### 建议的选题对照顺序

按「与现有项目储备的复用度」排：

1. **AI WORKS / 效率进化** — 方向为「用 AI 重构学习、研究与工作方式」，场景定位第一条即「校园学习」；阿里云特别赛题（Qwen 科研提效 / 认知增强）在技术上是 RAG + 工具调用 + 评测的 LLM 应用，与常见作品集项目同构。
2. **AI LIVES / 智能日常** — 偏手机、穿戴、端侧设备，需硬件或设备层能力。
3. **AI CREATES / 创意造物** — 需多模态生成与本地算力（AIPC）。
4. **AI FOR ALL / 科技无碍** — 特别赛题未揭晓，命题不确定。

竞品密度提示：AI WORKS 的方向（AI 辅助学习 / 工作效率）是学生最易想到的，作品大概率扎堆。差异化应落在**产品边界与机制设计**，而非「AI 帮你做计划」这类通用表述。
